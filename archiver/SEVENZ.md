# Минимальный многофайловый профиль 7z

Минимальный Copy/BZip2-профиль реализован на Goose в `sevenzip.goose` и отдельном
Windows x64 CLI `sevenzip_cli.goose` (`g7z`). Существующий `garchive` продолжает
работать с `GARC0001`. Стандартный BZip2 и его буферы описаны в [BZIP2.md](BZIP2.md).

Пользователь выбрал распаковку обычным 7-Zip. Поэтому используем стандартный
контейнер 7z 0.4 и стандартные методы. Решения: [ADR-001](ADR-001-7Z.md).
Основа — официальные [7zFormat.txt](https://github.com/ip7z/7zip/blob/main/DOC/7zFormat.txt),
[7zOut.cpp](https://github.com/ip7z/7zip/blob/main/CPP/7zip/Archive/7z/7zOut.cpp)
и [реестр методов](https://github.com/ip7z/7zip/blob/main/DOC/Methods.txt), проверенные 2026-10-23.

## Что входит

| Возможность | Начальный профиль |
|---|---|
| Обычные файлы и относительные пути | Да |
| Каталоги, в том числе пустые | Да, явные записи |
| Пустые файлы | Да, без потока |
| Unicode | UTF-16LE в 7z, UTF-8 в Goose; включая surrogate pairs |
| Размеры и CRC32 | Для каждого непустого файла |
| Время изменения | Необязательное свойство MTime; не подставлять фиктивное время |
| Хранение без сжатия | Copy, ID `00`; fallback для невыгодного сжатия |
| Сжатие | Стандартный современный BZip2, ID `04 02 02`; по умолчанию уровень 3 |
| Сжатие ZSTD | ID `04 F7 11 01` (7-Zip-zstd); кадры стандартного zstd (RFC 8878), свойство 1 байт; `zstd.goose` |
| Solid, сжатый/зашифрованный индекс, пароли, тома, SFX | Следующие этапы |
| Символические/жёсткие ссылки, ACL, альтернативные потоки | За пределами начального профиля |

## Раскладка файла

```text
0                   32                              32 + NextHeaderOffset
+-------------------+-------------------------------+----------------------+
| SignatureHeader   | PackedStreams: файл A, B, ... | Header / FilesInfo   |
| 32 байта          | только непустые файлы         | обычный, несжатый    |
+-------------------+-------------------------------+----------------------+
```

Индекс отделён от данных. У потока нет собственного имени: соответствие задают
порядок файлов без EmptyStream и порядок потоков. Сначала записываем данные и
индекс, затем заполняем начальные 32 байта. Для текущего whole-file API это правка
буфера перед единственной атомарной записью; для будущего файлового API — seek.

### SignatureHeader

Все фиксированные целые little-endian. Это точные поля 7z, без своих добавлений.

| Смещение | Байты | Значение |
|---|---:|---|
| 0 | 6 | `37 7A BC AF 27 1C` |
| 6 | 1 | Major = `00` |
| 7 | 1 | Minor = `04` |
| 8 | 4 | StartHeaderCRC = CRC32 байтов `[12,32)` |
| 12 | 8 | NextHeaderOffset, относительно позиции 32 |
| 20 | 8 | NextHeaderSize |
| 28 | 4 | NextHeaderCRC, CRC32 точных байтов индекса |

В нашем профиле `NextHeaderOffset = сумма PackSizes`, а конец индекса совпадает
с EOF. Не путать это с абсолютным смещением. Начальный заголовок и индекс
проверяются до выделения массивов по объявленным размерам.

### Целые и битовые массивы

`UINT64` внутри индекса — специальное число 7z, **не ULEB128**. `n` ведущих
единиц первого байта задают число последующих low-order байтов; оставшиеся
биты первого байта дают старшую часть. При первом байте `FF` следуют все 8 байтов.
Выбирать кратчайшую запись; собственный читатель может ограничиться ею.

| Значение | Байты |
|---:|---|
| 127 | `7F` |
| 128 | `80 80` |
| 16383 | `BF FF` |
| 16384 | `C0 00 40` |
| 2^64 − 1 | девять `FF` |

Битовые массивы идут старшим битом вперёд: запись `i` использует
`0x80 >> (i % 8)` в байте `i / 8`; неиспользуемые младшие биты равны нулю.

## Дерево индекса

`N` — все записи файлов/каталогов, `S` — только непустые обычные файлы.
Значения ниже — ID полей; числа после них записываются как UINT64, если не
оговорён фиксированный размер. Прямоугольные скобки обозначают условную часть.

```text
01 Header
  [если S > 0:
    04 MainStreamsInfo
      06 PackInfo
        PackPos = 0; NumPackStreams = S
        09 Size; PackSizes[S]
        00 End
      07 UnPackInfo
        0B Folder; NumFolders = S; External = 0 (BYTE)
        Folder[S]
        0C CodersUnPackSize; OriginalSizes[S]
        0A CRC; AllAreDefined = 1 (BYTE); CRC32[S] (фиксированные u32 LE)
        00 End
      08 SubStreamsInfo
        00 End
      00 End
  ]
  [если N > 0:
    05 FilesInfo; NumFiles = N
      [0E EmptyStream; PropertySize; bitmap[N]]
      [0F EmptyFile; PropertySize; bitmap[число EmptyStream]]
      11 Name; PropertySize; External = 0 (BYTE); Names[N]
      [14 MTime; PropertySize; Defined; External = 0; Times]
      00 End
  ]
  00 End
```

Каждое свойство FilesInfo имеет длину в байтах, включая байт External или
Defined и bitmap, когда они есть. Размеры секций MainStreamsInfo так не кодируются:
их читает структурный парсер по ID и завершающим End. Нельзя универсально
пропускать незнакомый структурный ID как свойство FilesInfo.

Наш writer создаёт пустой архив с индексом `01 00`, без потоков, размером 34 байта.
Reader также принимает 32-байтовый вариант 7-Zip с нулевыми NextHeaderOffset,
NextHeaderSize и NextHeaderCRC. Все записи могут быть пустыми: тогда FilesInfo
есть, а MainStreamsInfo отсутствует.

### Один кодер на Folder

В 7z Folder — группа кодеров, **не каталог файловой системы**. Для каждого
непустого файла здесь один простой кодер: один вход, один выход, без свойств
и связей. Описание Copy: `01 01 00` (число кодеров, flags/длина ID, ID).
Для BZip2: `01 03 04 02 02`. Для ZSTD: `01 24 04 F7 11 01 01 00` (флаг `24` = ID 4 байта + свойства; свойство 1 байт). Байты ID метода идут как в реестре;
это не little-endian u32. PackSize и OriginalSize остаются отдельными полями.

В SubStreamsInfo `08 00` означает значения по умолчанию: один файл на Folder.
Его размер и CRC берутся из UnPackInfo. Отдельные PackInfo CRC и повторные
CRC SubStreamsInfo в этом профиле не нужны. Позиция потока `j`:
`32 + PackPos + сумма PackSizes[0:j]`.

Читатель также принимает CRC файлов из SubStreamsInfo вместо Folder CRC, как
пишет обычный 7-Zip: для одного подпотока CRC наследуется от Folder, если
определён там; остальные digest берутся из SubStreamsInfo. NumUnPackStream
можно явно записать, но все значения должны быть 1. Отсутствующий digest файла
не входит в поддерживаемый профиль.
Если PackInfo содержит CRC, он проверяется по **сжатым** байтам, а не сравнением
с CRC исходного файла. Для Copy оба значения совпадают; для BZip2 обычно различаются.

### Файлы, имена и время

- Непустой файл: EmptyStream = 0; следующий поток соответствует ему.
- Пустой файл: EmptyStream = 1, соответствующий EmptyFile = 1.
- Каталог: EmptyStream = 1, соответствующий EmptyFile = 0.
- При отсутствии пустых записей оба свойства можно опустить. Если пустые
  записи есть, наш writer пишет оба bitmap, даже когда EmptyFile весь нулевой.
- Name содержит один байт External = 0, затем N строк UTF-16LE, каждая с
  двухбайтовым нулём. Счётчик длины имени отдельно не записывается. Нужно ровно
  N корректных строк; surrogate pairs преобразуются целиком, NUL внутри имени запрещён.
- MTime: один байт AllAreDefined; если он нулевой, далее bitmap[N]; затем
  External = 0 и значения только для определённых записей. Каждое значение —
  фиксированный u64 FILETIME: число интервалов 100 нс от 1601-01-01 UTC.
  Если время неизвестно для всех записей, свойство отсутствует.
- CRC32 такой же, как в текущем GARC0001: CRC-32/ISO-HDLC. Для пустых файлов
  отсутствие потока уже задаёт пустое содержимое; отдельный digest не пишется.

Writer формирует однозначный порядок записей по относительным UTF-8 путям и
тот же порядок непустых потоков. Родительские каталоги добавляются явно без
дубликатов. Каталоги не заканчиваются `/`. Разделитель пути внутри архива — `/`.

## Внутренние данные Goose и границы первой реализации

`Entry` хранит смещение/длину пути, flags, `size` исходного содержимого,
`offset`/`packed` диапазон архивного потока, `method` (0 Copy, 1 BZip2, 2 ZSTD), CRC
исходного файла и MTime. При записи offset адресует входной contents;
packed/method входных записей не задают политику кодирования. `write` сохраняет
Copy-only контракт; `write_with_level(..., level)` выбирает Copy/BZip2/ZSTD.
Переменные арены используются для путей, индекса, данных и рабочих блоков;
таблицы кодеков остаются фиксированными. Не хранить по копии пути на каждое поле
и не держать ссылки на элементы арены во время её роста.

Начальная политика памяти: до 65,535 записей, до 8 МиБ индекса и до 64 МиБ
суммарного распакованного содержимого; packed bytes тоже ограничены 64 МиБ.
Проверять отдельно packed bytes и арены
имён. Это ограничения программы, не 7z; 64-битные поля сохраняем. Whole-file I/O
пока не ограничивает размер первоначального чтения. Вывод для Copy ограничен
суммой данных и индекса. Потоковый файловый API — отдельная задача.
Собственный writer не превышает размер Copy: BZip2 и ZSTD выбираются только при выигрыше
у Copy (с учётом байтов ID: 2 для BZip2, 7 для ZSTD) и меньший из двух побеждает. Пробный поток пишется в выход архива,
при fallback длина откатывается; полной копии candidate нет. Файлы читаются
непосредственно в contents. На извлечении все CRC проверяются до создания дерева,
затем выбранные сжатые файлы декодируются повторно по одному.

Стандартный `os` в Goose `94cc64d` не даёт stat/lstat или get/set mtime.
`gswinfiles.goose` добавляет прямые Win32-вызовы на Goose: проверку типа и
reparse points, абсолютные пути, ordinal-сравнение и чтение/установку MTime.
Первый файловый CLI поддерживает Windows x64 и локальные дисковые пути; UNC и
переносимый POSIX-адаптер остаются будущей работой. Рекурсивный обход реализован
очередью, без владения динамическими буферами в рекурсивных вызовах. `list_dir`
разделяет имена LF: непредставимые таким способом имена приводят к отказу,
а не молчаливому пропуску. Ограничения длины пути Win32 сохраняются.
`gswinargs.goose` получает Unicode-аргументы непосредственно через Win32;
ограничение ANSI argv рантайма не теряет кириллицу и emoji в путях и фильтрах.

## Чтение и извлечение

Наш первый читатель поддерживает этот профиль, не весь 7z. Неизвестный кодек,
EncodedHeader, solid, шифрование, сложный Folder или внешний индекс дают
`unsupported_feature`. Неверная длина, CRC или структура — `invalid_archive`.
Сначала проверяется и полностью разбирается индекс; затем разрешается чтение данных.

Проверки: число потоков равно числу непустых файлов; все размеры и диапазоны
проверены без переполнения; суммы packed-размеров совпадают с NextHeaderOffset;
число имён/bitmap/размеров/CRC согласовано. CRC файла сверяется после декодирования.
Первая версия требует точного EOF, отсутствия SFX и дополнительных потоков.
Это ограничение нашего профиля, а не критерий испорченности любого стороннего 7z.

Для извлечения допустимы только относительные пути внутри нового каталога назначения:
без `..`, абсолютного пути, drive/UNC, NUL и конфликтов файл/каталог. Проверять
совпадения путей и коллизии целевой файловой системы до записи. Не проходить
через существующие symlink/reparse-компоненты. Существующий каталог назначения
и существующий выходной архив не перезаписываются. Каждый файл записывается
атомарно после проверки всех CRC до начала извлечения; при
ошибке I/O ранее извлечённые файлы могут остаться — атомарность всей папки не обещается.
Время каталогов восстанавливается после их содержимого. Проверки путей не
являются блокировкой против одновременного изменения файловой системы другим процессом.
Копирование ACL/разрешений и восстановление CTime/ATime не реализовано; простые
свойства 7-Zip для времени, атрибутов и выравнивания читаются, специальные типы
файлов/reparse flags отклоняются.

Реализованный отдельный CLI: `g7z a OUT.7z ROOT`, `g7z l ARCHIVE`,
`g7z t ARCHIVE`, `g7z x ARCHIVE NEW_DEST [REL_PATH...]`. Writer собирает всё
содержимое ROOT, пути вычисляет относительно него. Выбор при извлечении принимает
точное имя файла или каталога с потомками; ненайденный выбор отклоняется до записи.
Создание архива по выборочному списку входов остаётся расширением.

## Почему нельзя непосредственно использовать наш поток

ID BZip2 означает стандартный битовый формат BZip2. У нынешнего GARC0001 другие
заголовки, BWT с опущенным sentinel, таблицы и фрейминг. Для совместимого BZip2
нужны RLE перед циклическим BWT, его таблица используемых байтов, EOB, селекторы
таблиц Хаффмана и стандартные CRC/маркеры блока и потока. Это следующий кодек на
Goose, не переименование нынешнего метода. Контейнер при его добавлении остаётся
тем же; при увеличении файла весь его поток сохраняется методом Copy.

## Проверка совместимости

2026-10-23 прототип раскладки проверен официальным `7zr.exe` 26.04 (x86):
шесть архивов, 159 записей; просмотр, тестирование и извлечение с точной
сверкой содержимого. Покрыты пустой архив, только пустые записи, несколько
потоков, кириллица/emoji, необязательное MTime, bitmap длиннее байта и переход
UINT64 за 127/16383. Три повреждения областей StartHeader, Header и data
отклонены. Это первоначальное доказательство раскладки Copy; ниже — проверки
реализации Goose. Отчёт/прототип: ignored `build/sevenz-layout/`.

Официальный инструмент получен с `https://www.7-zip.org/a/7zr.exe`, без установки.
SHA-256: `256feca8e274e5da655e2a284fabafd9f554365eb164862089dacd4e8276d282`.
Воспроизводимые минимальные векторы: [sevenz-copy-vectors.json](sevenz-copy-vectors.json).
Проверка не скачивает и не устанавливает инструменты:

```powershell
python -B archiver/sevenz_layout_check.py --sevenzip build/sevenz-layout/7zr.exe --out build/sevenz-layout/replay
```

Обе нативные сборки Goose проверены в двух направлениях: наши архивы открыты и
извлечены 7zr 26.04; его `a -t7z -mx=0 -ms=off -mhc=off` прочитаны и извлечены
Goose с проверкой содержимого и времени файлов/каталогов. На каждую сборку:
3 контрольных вектора, 3 дерева в каждом направлении, 109 отказов повреждённых
входов, 5 конфликтов путей, 120 проверок изменённых заголовков, 6 файловых отказов
и выборочное извлечение. В том числе проверены junction, существующие цели,
Unicode case-collisions, 130+ файлов и границы чисел/bitmap. Запуск:

```powershell
goose run archiver/sevenz_test.goose
goose build archiver/sevenzip_cli.goose -O2 -o build/archiver/g7z.exe
python -B archiver/verify_sevenz.py --exe build/archiver/g7z.exe --sevenzip PATH_TO_7ZA --out build/sevenz-layout/goose-release
python -B archiver/verify_sevenz_bzip2.py --exe build/archiver/g7z.exe --sevenzip PATH_TO_7ZA --out build/sevenz-layout/bzip-release
```

Повторить с `--debug`; отчёты сохраняют хеши исходников и обоих исполняемых файлов.
Тест junction требует разрешения на её локальное создание; удаляется только сама
junction, без рекурсивного удаления. BZip2 дополнительно проверен полным 7za 26.05,
Python bz2 и в обоих направлениях, включая смешанные Copy/BZip2, размеры,
PackInfo CRC и Unicode-аргументы. Подробные числа и команды — в [BZIP2.md](BZIP2.md);
reduced `7zr` не содержит BZip2. Архивы 7-Zip по умолчанию могут
использовать LZMA2 и EncodedHeader и не входят в первый читатель.
