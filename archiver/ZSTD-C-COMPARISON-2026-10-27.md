# Сравнение сгенерированного C и libzstd — 2026-10-27

На одинаковых GCC 16.1.0 `-O2 -g` libzstd быстрее на исследованных блоках,
но это сравнение разных алгоритмов и API, а не доказательство, что язык C
сам по себе быстрее Goose. Замеры: [ZSTD-SAME-GCC-2026-10-27.md](ZSTD-SAME-GCC-2026-10-27.md).
Сопоставлены C, сгенерированный из текущего Goose `-O2`, исходный C libzstd
1.5.7 и профили инструкций получившихся бинарных файлов.

## Что действительно выполнялось

Профилировщик приостанавливал основной поток собственных дочерних процессов;
по два запуска около четырёх секунд, случайный интервал 0,7–2,3 мс. Адреса
нормализованы по базе EXE или DLL и разрешены через GCC `addr2line -i`.
Профиль libzstd — наша GCC-сборка без отдельного ассемблера; замерялся
вызов `ZSTD_decompressDCtx` с сохраняемым контекстом. Goose использует
текущий decoder. Выход каждого профилируемого процесса совпал с исходником.

- **g7z, уровень 3, только Huffman-литералы:** 3350 из 4399 сэмплов внутри
  DLL разрешились непосредственно в
  `HUF_decompress4X2_usingDTable_internal_fast_c_loop`. В нашей программе
  4134 из 4262 сэмплов внутри EXE разрешились в `zstd_huf_stream4_g4`.
  В остальных сэмплах находятся inline helpers и подготовка. Это доли
  выборки внутри каждого бинарного модуля, не время двух функций напрямую.
- **Исходники, уровень 3, последовательности с сырыми литералами:** у
  libzstd разрешаются `ZSTD_decodeSequence`, `ZSTD_execSequence`, bitstream
  и `ZSTD_wildcopy`; 322 из 4090 сэмплов разрешились в `_mm_storeu_si128`.
  У Goose 3338 из 4317 сэмплов разрешились в `zstd_sequences_g4`, остальные
  в частности в `gs_memcpy` и helpers загрузки. `_mm_storeu_si128` подтверждает
  исполнение SSE2-store в этом профиле, но не доказывает стоимость или долю
  выигрыша за счёт SIMD.

Сырые сэмплы, вне-модульные адреса, ошибки и разрешённые inline-цепочки:
ignored `build/zstd-profile-current/{lib-huf,lib-seq,goose-huf,goose-seq}/`.
Профилирование изменяет время работы; использовать проценты с осторожностью.

## Основные различия

**Huffman.** В нашем `huf_stream4` один lookup выдаёт один символ на поток;
в сгенерированном C для каждого символа остаются проверки доступности окна,
кэшированной области, таблицы и позиции выхода. GCC может убрать или
передвинуть отдельные проверки, поэтому сам вид C не является подсчётом
выполненных инструкций. libzstd на исследованном блоке выбирает X2-таблицу:
один lookup может выдать два символа, быстрый цикл развёрнут по четырём
потокам и нескольким lookup до очередного обновления битового регистра;
границы проверяются пакетами, хвост обрабатывается отдельно. Это сочетание,
а не только «два символа». Наш ранний простой X2-прототип был медленнее и
не повторял такую организацию цикла.

**Последовательности.** libzstd в записи `ZSTD_seqSymbol` хранит заранее
подготовленные базовые значения, количество дополнительных битов и переход
состояния; наш C читает три массива и отдельно использует таблицы базовых
значений/битов. Проверенные ранее варианты упаковки лишь текущих полей FSE
дали регрессию: они не эквивалентны полной предвычисленной таблице libzstd.
libzstd также имеет ограниченный быстрый путь копирования блоками 16 байт;
его `wildcopy` рассчитан на разрешённый запас чтения/записи. Наш grow-only
выход не даёт права без проверки писать за допустимую область: точную
адаптацию нужно проектировать с сохранением гарантий буфера и overlap.

**Проверки.** `GS_IDX` в этом release-C остаётся проверкой индекса, если
её не устранил компилятор; проверки диапазона срезов тоже видны в C.
При этом `gs_add_i64` и другие арифметические helpers в release — макросы,
не вызовы и не debug-проверки переполнения. Нельзя объяснить весь разрыв
количеством строк C или приписать его однозначно проверкам компилятора.

Источники: ignored `build/zstd-huf4-unrolled/bench.c` и
`build/libzstd-source/zstddeclib.c`; сравнительные бинарные файлы и символы
сохранены рядом. Следующий измеримый эксперимент — независимый быстрый
Huffman-путь с пакетными проверками и X2-таблицей с корректной обработкой
границ, отдельно от короткого безопасного пути; затем сравнение предвычисленных
таблиц последовательностей и безопасного блочного копирования.
