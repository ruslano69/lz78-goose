# ADR-001: Многофайловый контейнер, совместимый с 7-Zip

**Status:** Accepted — минимальный Copy/BZip2-профиль реализован и проверен на Goose.
**Date:** 2026-10-23
**Deciders:** Пользователь подтвердил совместимость с обычным 7-Zip.

## Context

Рабочий `GARC0001` сжимает один файл собственным BWT/MTF/RLE/Huffman-потоком.
Нужны несколько файлов, относительные пути, каталоги и извлечение отдельных файлов.
Обычный 7-Zip должен читать полученный архив без расширений. Переименование
`GARC0001` в `.7z` или присвоение ему идентификатора BZip2 совместимости не даёт.

## Decision

- Создавать настоящий 7z версии 0.4 с открытым индексом в конце архива.
- Один непустой файл — один независимый packed stream и один 7z Folder с одним
  простым кодером и одним выходом. Здесь Folder — описание декодирования, не каталог.
- Первый этап: стандартный Copy (`00`) для проверки контейнера без нового кодека.
- Этап сжатия: стандартный BZip2 (`04 02 02`), реализованный на Goose; при
  увеличении потока выбирать Copy. Выбор основан на близости к уже изученной
  BWT-цепочке. Отдельная реализация современного битового формата BZip2 проверена
  через libbz2 и полный официальный 7za; ограничения читателя указаны в BZIP2.md.
- Каталоги и пустые файлы хранить в FilesInfo без потока данных. Имена на диске
  UTF-16LE, во внутреннем API Goose — UTF-8. Время изменения — необязательное.
- Не включать solid, шифрование, сжатие заголовка, SFX, тома, ссылки, ACL и
  изменение архива на месте в начальный профиль.
- Существующие `GARC0001`, команды и проверки остаются отдельным рабочим режимом.

## Options Considered

| Вариант | Совместимость | Работа | Решение |
|---|---|---|---|
| Свой контейнер вокруг GARC0001 | Только наш декодер | Небольшая | Не выполняет требование пользователя |
| Настоящий 7z + частный ID кодека | Нужен сторонний кодек в 7-Zip | Средняя | Не выполняет требование распаковки обычным 7-Zip |
| Настоящий 7z + Copy, затем BZip2 | Стандартные методы 7z | Контейнер умеренный; кодек — отдельная работа | Принят |
| Настоящий 7z + LZMA2 | Стандартный метод 7z | Новый алгоритм сжатия | Возможное расширение, не начальный этап |

## Trade-off Analysis

Раздельные потоки упрощают проверку, адресацию, выборочное извлечение и ограничение
рабочей памяти; множество маленьких похожих файлов сжимаются хуже, чем в solid.
Открытый индекс можно прочитать без декодирования содержимого. Copy даёт настоящий
многофайловый архив, но не сжатие. Совместимый BZip2 не равен нынешнему собственному
потоку: нужны его RLE1, циклический BWT, таблица используемых байтов, EOB,
селекторы таблиц Хаффмана, точный битовый поток и собственные CRC/фрейминг BZip2.

## Consequences

- Файлы, пути и методы отделены от алгоритма сжатия; дальнейшие кодеки не требуют
  придумывать новый контейнер или переписывать список файлов.
- Поддержка чтения первоначально ограничена нашим профилем. Чтение всех архивов,
  создаваемых 7-Zip с настройками по умолчанию, не обещается.
- API `os` в исследованном Goose `94cc64d` предоставляет whole-file I/O и
  перечисление имён, но не stat/lstat или mtime. `gswinfiles.goose` решает
  проверку типа/reparse points и чтение/установку MTime прямым Windows x64 FFI.
  Переносимый файловый слой и потоковый I/O остаются отдельной работой.
- Ограничения первой реализации — политика приложения, не ограничения формата 7z.
